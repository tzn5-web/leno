# AtelierData — independent Ghidra IAT evidence gate (2026-10-31)

## Scope and provenance

This change adds `ghidra_iat_instruction_evidence.py` and 14 synthetic regression tests. It is separate from the vehicle/procedure/schematic development lane. It reads a **private**, SHA256-verified owner-authorized PE32 executable and the private JSON reports generated by `pe_file_io_xrefs.py` and `tools/ghidra/AtelierData_IAT_Instruction_Check.java`. It does not execute the target, open the blocked `autodata_part_0016.zip`, patch binaries, bypass licensing, or publish proprietary content.

## New checks

- Mandatory SHA256 equality across the PE bytes and both private report fields.
- Strict x86 PE32/section bounds, unambiguous executable-section address mapping, six-byte `FF 15`/`FF 25` candidate verification and the exact IAT operand.
- Candidate ordering, addresses, symbols, count, uniqueness and Ghidra mnemonic consistency.
- Independent recomputation of reported recognized-instruction and reference counts.
- Bounded input size (64 MiB PE, 32 MiB per JSON, 200,000 candidates) and output-overwrite protection.
- Public output contains aggregate counts and explicit negative assertions; private offsets, addresses, program names, DLL names and bytes are not exported.

## Verified in this development iteration

The 14 new synthetic unit tests passed locally on Python. They exercise valid recognized/unrecognized candidates, altered PE/hash, wrong operands/offsets, mismatched addresses, forged counts, invalid types, duplicate candidates, unmapped candidates, incorrect mnemonics and invalid PE headers. These tests **do not** attest that the original PE was processed by Ghidra.

Windows CI runs `unittest discover -s projects/atelierdata -p 'test_*.py' -v` on every push to this branch and rebuilds `AtelierData.exe`. The GitHub Actions result must be checked separately before claiming Windows PASS.

```powershell
python projects/atelierdata/ghidra_iat_instruction_evidence.py --pe C:\PRIVATE\ADBCD.exe --expected-sha256 a505bbc4f8678713f352faa8fc70337d9edbe5e0ebd23ba305ca3bccd0f6fce4 --private-iat C:\PRIVATE\iat-private.json --private-ghidra C:\PRIVATE\ghidra-private.json --public-output C:\PRIVATE\iat-verified-public.json
```

**Evidence limitations:** this validator checks raw PE bytes and consistency of the claimed Ghidra observations, not whether Ghidra imported the identical original program. The existing Ghidra script records only the expected SHA256 from the private report, not an independently checked imported-program identity. Therefore `ghidra_imported_program_identity_independently_verified=false` is always explicit. A recognized `CALL` to `LoadLibraryA` is not proof of dynamic API resolution, a reachable loader, an IDF parser, a decoder, or an installation entitlement. No original `.IDF` format has been identified.
