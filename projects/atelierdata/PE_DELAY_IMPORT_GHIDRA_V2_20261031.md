# AtelierData: PE delay imports + Ghidra evidence verification v2 (2026-10-31)

## Scope and provenance

This is a **static interoperability investigation**, not an IDF decoder or a method
to disable licensing. The owner-supplied original executable has previously been
verified with SHA256:

`ADBCD.exe`: `a505bbc4f8678713f352faa8fc70337d9edbe5e0ebd23ba305ca3bccd0f6fce4`

Earlier REA 6.8.0 analysis reported **52 partial/uncertain delay-import observations**.
It did **not** establish the file loader, format, encryption or compression used
for proprietary IDF files. Previous raw PE triage found 43 candidate FF15/FF25
byte sequences, which are not validated x86 instructions.

## New implementation

- `pe_delay_import_audit.py`: bounded parser for PE32 delay-load directory
  index 13. Supports both RVA-based and VA-based delay descriptors and named
  and ordinal imports. Reports unmapped/malformed metadata as **PARTIAL**, not
  as valid imports. Limits file size, descriptors, thunk counts and names.
- Public JSON contains **counts, classifications and SHA256 only**. The
  optional private JSON contains DLL names, imported symbols and offsets.
- Input SHA256 is mandatory. Output paths cannot overwrite the original PE.
- `pe_file_io_xrefs.py` now includes `iat_va` in **private** candidate records
  so that the exact FF15/FF25 operand can be checked independently.
- `tools/ghidra/AtelierData_IAT_Verified.java` verifies the original file's
  SHA256 and binds the Ghidra-imported program to it using Ghidra's executable
  MD5 metadata. It validates opcode, instruction boundary, six-byte length,
  and exact 32-bit IAT operand. It separately counts Ghidra references to IAT.
  It writes private detailed evidence and optionally a public aggregate report.
  Unlike the older script, matching a report SHA256 alone is **not sufficient**.
- Eight new synthetic tests cover absent/RVA/VA/malformed/unmapped delay import
  descriptors, ordinal imports, undersized directories, SHA256 rejection and
  public/private output isolation. Existing
  PE triage test now checks private `iat_va` and public redaction.

**Important status distinction:** The new Python parser and Ghidra v2 script
have been committed to GitHub and added to the Windows test workflow. No
new run of REA or Ghidra against the private original was performed in this
iteration. The Ghidra v2 script is **not yet runtime-validated in Ghidra**.
The synthetic tests are not a substitute for analysis of the real executable.
Do not claim the 52 REA warnings are resolved until a SHA256-checked private
execution of the new static parser confirms the outcome.

## Reproduce privately, without running the original

Run from the repository root, with the original file only on a private local
filesystem or authorized private Drive workspace:

~~~powershell
$sha = "a505bbc4f8678713f352faa8fc70337d9edbe5e0ebd23ba305ca3bccd0f6fce4"
python projects/atelierdata/pe_delay_import_audit.py --pe "C:\PRIVATE\ADBCD.exe" --expected-sha256 $sha --public-output "C:\PRIVATE\delay-public.json" --private-output "C:\PRIVATE\delay-private.json"
python projects/atelierdata/pe_file_io_xrefs.py --pe "C:\PRIVATE\ADBCD.exe" --expected-sha256 $sha --public-output "C:\PRIVATE\iat-public.json" --private-output "C:\PRIVATE\iat-private.json"
python -m unittest discover -s projects/atelierdata -p "test_pe_delay_import_audit.py" -v
~~~

For an existing **private** Ghidra PE32 project imported from the same
SHA256-verified file, use the `AtelierData_IAT_Verified.java` post-script with:

1. Private `iat-private.json` regenerated by the updated Python scanner.
2. Private `ghidra-iat-private.json` output path.
3. Expected original SHA256.
4. Exact local original `ADBCD.exe` file path.
5. Optional public aggregate JSON output path.

Ghidra must have analyzed/disassembled the relevant code for instruction
recognition. A zero count without analysis does not establish that the
candidate bytes are invalid. No executable, IDF, DLL, license data, private
addresses or detailed reports belong in the public GitHub repository.

## Current blockers

- No authenticated, authorized Windows installation of the original has been
  demonstrated. Package 0016 remains blocked by Google Drive and must not
  be bypassed.
- No original-IDF loader or decoder has been identified, and no right to
  redistribute the proprietary data has been established.
- New Ghidra verification has not been executed against the private binary.
- A new Windows Actions run must be checked before declaring CI PASS for
  these changes.

The independent AtelierData catalog can continue to accept only authorized
documents and original technical records. Neither this investigation nor
the existence of Chilkat crypto imports implies any IDF decoding success.
