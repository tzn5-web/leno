- \`dial_1_circle_240x240/\` — **248 entries**
- \`dial_2_square_240x240/\` — **248 entries**

The circular template contains subdirectories for \`battery\` (0.png–4.png), \`stepnum1\`–\`stepnum5\`, \`stepproccess\`, \`iconstep\`, \`iconbluetooth\`, \`timehour1/2\`, \`timemin1/2\`, \`timeday1/2\`, \`timemonth1/2\`, \`week\`, \`ampm\`, \`background\`, \`preview\`, and other assets. Empty \`config_WxH_XxY.txt\` filename markers encode element dimensions and position. This is **direct evidence of dynamic hour/date/step/battery widgets in a packaged GloryFit dial**. It is not proof every app/watch firmware supports arbitrary custom layouts.

The downloaded dial \`DialCustom_240x240_90.zip\` holds a separate \`dial_10027_circle_240x240/\` layout with **124 ZIP entries**. That particular downloaded ZIP has hour/minute and date/week layers but not dedicated heart/step/battery/weather layers.

### Cached binary \`D1898001.bin\`

The extracted 343,944-byte file parses as:

| Field | Value |
|---|---|
| header bytes | 24 |
| file identifier @0x00 | 189,801 (\`0x0002e569\`) |
| payload length @0x04 | 343,920, exactly file length minus 24 |
| CRC32 @0x08 | \`bceaef79\`, verified over bytes from offset 24 |
| dimensions @0x0C | 240 × 240 |
| element-record table | 22 records, 24 bytes each |
| pixel data | big-endian RGB565, confirmed by rendering |
| 240×240 embedded images | 2, including a full-preview frame and a compositing/background frame |

A record provides an element ID, height, image-data offset, width, x/y position and frame count, plus fields not yet identified. RGB565 payload sizes agree with record dimensions × 2 bytes/pixel × frame count. Some image payloads are shared between multiple element records.

The binary preview visually shows heart-rate, calories, steps, weather, battery, date and time. **Do not assume these values are live, nor assume the binary can be flashed, solely from the preview.** Dynamic bindings and the BLE upload procedure still need independent testing.
